# Windows implants coverage

Pinned Windows source-reference coverage for Havoc, Gh0st, TinyNuke, r77 and the selected mimikatz tree.

This snapshot contains **34 report/export pairs: 4962 kept + 730 removed = 5692 image functions**. Counts describe retained functions, including documented residues; they are not a count of unique project implementations. Each export is marked `is_library=true`.

Coverage is limited to the source components below. PE analysis containers with no entry point or unresolved references are not runnable releases. A `.dll` analysis filename does not establish coverage of the upstream DLL startup, service installation or raw-payload format. Compiler/architecture axes are justified by the >=10-instruction PicHash matrices in the recipe docstrings.

### Translation-unit audit

At pinned mimikatz commit `45c42c710fc3a9d7acdcd1f7acf966cc4ce07a49`,
`mimikatz/mimikatz.vcxproj` lists 114 C translation units. Exactly 112 have
`kuhl_m_` or `kull_m_` basenames; these are the selected MSVC references.
The other two are `mimikatz.c` and `../modules/sqlite3.c`, not missing helper
units. The project-file SHA-256 is
`179e0d2012b0ad10ba6c96a848755e16256fba4189b858fa2e6e6d44be1a8bec`.
The four committed mimikatz exports contain no `sqlite3` implementation names.
This closes the translation-unit inventory question within the approved
helper-tree scope; it does not claim a dispatcher, SQLite family or
`ext_server_kiwi` DLL build.

The follow-up audit added no images. Builds of working credential-theft
extensions, rootkit deployment programs and the remaining RAT program were
stopped at the audit stage by safeguards, before a compiler or CI job was
started. No compiler error is claimed for those unattempted targets.

## Integration and validation

[PR 104](https://github.com/familiary/mcrit-data/pull/104) carries this matrix. Its data-producing [Windows run](https://github.com/familiary/mcrit-data/actions/runs/42477643668) passed on both architectures, selecting only the batched Havoc entry recipe. All six output binary hashes and counts match the committed references; the compile/link logs confirm the required MSVC flags.

Local corpus tests passed (177 tests), family validation and provenance checks reported zero problems, and all 34 archives contained exactly one `.smda`. The last full deep scan covered 546 archives and reproduced exactly the pinned base's 26 findings with no additions: 15 Rust leakage findings, ten MSVC leakage findings and the missing Hidden README link. This is an unchanged nonzero baseline, not a clean full-corpus validation result.

Existing work owns the shared fixes: [Hidden documentation](https://github.com/familiary/mcrit-data/pull/22), [function exclusions](https://github.com/familiary/mcrit-data/pull/94), [MSVC EXE/stdio probes](https://github.com/familiary/mcrit-data/pull/80), [wide stdio probes](https://github.com/familiary/mcrit-data/pull/86) and the [kernel x86 baseline](https://github.com/familiary/mcrit-data/pull/111). These PRs have separate stacks and must be reviewed in their stated dependency order. They are not merged here. After integration, re-run provenance, corpus tests and the deep comparison before claiming the inherited findings closed.

No generated payloads or built binaries are committed. Temporary sources, SDK copies, build trees and artifact ZIPs were removed after conversion. Both data PRs remain for maintainer review; no merge, approval or issue closure is implied.
